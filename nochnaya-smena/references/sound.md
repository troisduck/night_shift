# Звук «Ночной смены»

## Тезис
Звук — второй прибор. Опытный оператор с закрытыми глазами должен понять, что с блоком: сколько насосов в работе, идёт ли пар на турбину, разгоняется ли реакция, есть ли тревога. Каждый звук отвечает на вопрос «что с блоком?» или подтверждает действие игрока. Декоративных звуков нет. Тишина — тоже информация: остановившийся насос слышно по пропаже его голоса.

Игровое допущение (честно): на настоящем БЩУ оборудование почти не слышно, щит далеко от машин. Мы слышим машзал и реактор «сквозь стены» и через динамик контроля — ради обучения. Автор может это решение пересмотреть.

## Непрерывные слои — каждый привязан к полю аудио-вида
| Слой | От чего зависит | Как звучит |
|---|---|---|
| Помещение БЩУ | `vent`, `mains` | тихий фильтрованный шум вентиляции, медленно «живёт» (±1–2 дБ); сетевой гул 100 Гц (сеть 50 Гц) с гармониками, очень тихо. Блэкаут — гул и вентиляция пропадают, тишина давит. |
| ГЦН ×4 | `pumps[i]` | лопастной тон ~95–100 Гц × обороты + шум потока; у каждого насоса своя частота, отсюда живые биения. Отказ — вой съезжает вниз за секунды (выбег), меняется рисунок биений. |
| Турбина | `turbine`, `steam` | синхронна с сетью, поэтому высота постоянна, а от нагрузки меняется плотность шума пара. Высота плывёт только при разгоне и выбеге. |
| Счёт нейтронов | `power` на малых уровнях, `countAudio` | щелчки, как у пусковых приборов: частота растёт с мощностью по логарифму. На пуске стрелка ещё на нуле, а разгон уже слышен. Выше ~1–5 % слой сам уходит. |
| Приводы стержней | `rods` | шаговые щелчки ~3–4 в секунду; вверх чуть выше по тону, вниз чуть ниже. |
| Компенсатор давления | `heaters`, `spray` | ТЭНы — щелчок контактора и сухое электрическое гудение; впрыск — шипение воды. |
| Сброс пара | `relief` | мощный шипящий рёв с низом — слышно даже сквозь стены. |
| ДГ ×3 | `diesels[i]` | тарахтение с частотой вспышек, растёт при наборе оборотов; пуск — выдох сжатого воздуха. |

## Разовые звуки и переходы
- Руки и события: тумблер, кнопка, крышка, ключ в замке, реле, квитирование, АЗ (реле, сброс 61 органа СУЗ, глухие удары при посадке), телефон диспетчера (механический звонок), «селектор» при реплике наставника — щелчок динамика и короткое шипение, а не писк.
- Каждый повтор чуть другой: высота ±3–5 %, громкость ±1–1,5 дБ, тайминг ±2 мс. Одинаковые до сэмпла повторы звучат как пулемёт.
- Переходы состояния звучат сами: включились ТЭНы — щёлкнул контактор; пропало питание — посыпались реле; пошёл насос — лязг пускателя.

## Сигнализация
- Уровни: 1 — предупредительная (короткий «дзынь» раз в 2–3 с), 2 — аварийная (прерывистый зуммер), 3 — АЗ и критические события (сплошной ревун).
- Сигнал звучит, пока его не квитировали. После квитирования наступает тишина, а табло горит ровно; при возврате в норму табло гаснет.
- Пока звучит аварийный сигнал, машины и помещение приглушаются примерно на 5–6 дБ: тревога всегда поверх.
- Одновременно звучат не больше 1–2 сигнальных голосов, и главный — самый важный.

## Микс (цифры — ориентиры скелета, замеренные самопроверкой)
- Мастер: громкость → срез ниже 20 Гц → лимитер (DynamicsCompressor) → выход. Пики ≤ −1 дБFS.
- Шины: машины «за стеной» (общий фильтр ~1,2 кГц), помещение, руки и события, сигнализация.
- Громкость: покой около −26 LUFS (допустимо −30…−20), тревога ≥ 6 LU над покоем (у скелета около +9).
- Частоты: гулы 40–200 Гц, машины до ~1,5 кГц, руки 1–4 кГц коротко, тревоги 300–3000 Гц. Долгая энергия в 2–5 кГц утомляет — только коротко.
- Ниже 40 Гц почти ничего: ноутбук этого не воспроизведёт, а лимитер начнёт «качать». Коричневый шум — через срез ~40–45 Гц.

## Браузер
- AudioContext создаётся и возобновляется по первому жесту; при сворачивании вкладки и на паузе игры — `suspend`.
- Выключатель звука и громкость в интерфейсе (по ТЗ).
- Шумовые буферы создаются один раз. Каждый кадр новых узлов не плодить, кроме коротких разовых звуков.
- Параметры меняются плавно (`setTargetAtTime`), а не присваиванием `.value` на ходу. У каждого разового звука атака и спад.
- Каждый значимый звук продублирован на экране лампой, табло или стрелкой: звук — второй канал, не единственный.

## Контракт движка (на нём держится самопроверка)
Основа — `assets/audio-engine-skeleton.js`. Встраивай его в игру целиком и развивай, а не пиши звук с нуля.

В игре:
```js
const snd = NightShiftAudio.live();          // контекст по первому жесту, тишина при свёрнутой вкладке
// в цикле отрисовки (20–30 раз в секунду):
snd.update(audioView(state));
// на действиях игрока:
snd.cue('tumbler');                          // tumbler, button, cover, key, relay, ack, mentor, scram, phone, diesel_start
// выключатель звука и пауза:
snd.setMuted(true);  snd.pause(true);
```

`audioView(state)` пишется в игре и переводит полное состояние в аудио-вид. Движок не знает ни физики, ни DOM, поэтому его можно рендерить оффлайн:

| Поле | Значение |
|---|---|
| `power` | тепловая мощность, доля номинала 0…1,1 (на пуске до 1e-7) |
| `pumps` | обороты четырёх ГЦН, 0…1 |
| `turbine` / `steam` | обороты турбины / расход пара, 0…1 |
| `rods` | −1 вниз, 0 стоят, 1 вверх |
| `heaters` / `spray` | ТЭНы / впрыск КД, 0…1 |
| `relief` | открытие сброса пара, 0…1 |
| `diesels` | обороты трёх ДГ, 0…1 |
| `vent` / `mains` | вентиляция БЩУ / питание собственных нужд, 0…1 |
| `countAudio` | динамик счёта нейтронов: true / false / не задан (сам на малой мощности) |
| `alarms` | `[{id, level: 1|2|3, acked}]` — активные сигналы |

Для проверки страница отдаёт `window.NightShiftAudio.create(ctx)` → `{update(view, when), cue(name, when, opts), setVolume, setMuted, dispose}`. Всё планируется по `when`, поэтому один и тот же код звучит в игре и рендерится оффлайн.

Новый слой — новое поле аудио-вида; старые поля не ломай. Для нового звука допиши сценарий проверки в JSON и передай `--scenario путь.json`:
```json
{
  "name": "kd", "duration": 20,
  "keys": [{"t": 5, "mode": "step", "set": {"heaters": 1}},
           {"t": 12, "mode": "lerp", "set": {"pumps.2": 0}}],
  "cues": [{"t": 3, "name": "tumbler"}, {"t": 3.8, "name": "tumbler"}],
  "events": [{"t": 5, "label": "ТЭНы включились"}],
  "steady": [[0.5, 2.8]],
  "repeat": ["tumbler"]
}
```
Здесь `mode` описывает отрезок, который кончается на ключе: `step` — скачок в момент t, `lerp` — линейно от предыдущего ключа, `log` — по логарифму (для мощности на пуске). Если `base` не задан, это полная мощность.

## Признаки ИИшного звука → чем заменить
1. Голые осцилляторы «пик-пик» на действиях → механические щелчки из коротких фильтрованных шумовых всплесков и низкого удара.
2. Щелчки на старте и стопе (нет огибающей), скачки `.value` → атака и спад рампами 2–10 мс, параметры через `setTargetAtTime`.
3. Аркадные звуки: восходящее арпеджио за успех, «вау-вау» за провал, лазеры, «вжух» → успех — подтверждение от станции (щелчок синхронизации, сухая реплика), провал — настоящие последствия (клапан, каскад АЗ).
4. Sci-fi-пэды, «эпичный эмбиент», завывание как у терменвокса → машинные звуки с физикой: основной тон и гармоники от оборотов, шум от расхода.
5. Мёртвая петля: гул не меняется от состояния → каждый слой привязан к полю аудио-вида, плюс медленная случайная жизнь.
6. Всё одной громкости, тревога тонет в гуле → шины, приоритеты, приглушение под тревогу.
7. Звук на каждое наведение мыши → звук только на действие с физическим смыслом.
8. Одинаковый писк 1 кГц для всех тревог → три разных голоса по уровням и квитирование.
9. Белый шум как «звук реактора» → цветной шум (розовый, коричневый) через фильтры с резонансами.
10. Абстрактное «значение → высота тона» (температура пищит выше) → высота только от физической причины (обороты). Единственный абстрактный канал — счёт нейтронов, и это настоящий приборный принцип.
11. Реверб и эхо «для атмосферы» → сухая комната, машзал приглушён фильтром «стены».
12. Идеально одинаковые повторы → разброс на каждом повторе.
13. Клиппинг при наложении → лимитер, запас по уровню, ограничение числа голосов.
14. Музыка поверх станции → в игре музыки нет: станция и есть саундтрек.
15. Роботизированный голос браузера (`speechSynthesis`) у наставника → текст и щелчок селектора.
16. Внешние звуковые файлы и вшитые записи → синтез в Web Audio: один файл без зависимостей, каждый раз чуть по-разному.

## Проверка: я не слышу — значит, меряю
`audio_check.py` (его запускает `selfcheck.py`) рендерит движок оффлайн в Chromium по двум сценариям:
- `default`, 48 с: ровная работа → тумблеры → стержни → отказ ГЦН-3 → квитирование → сброс пара → АЗ → блэкаут → пуск ДГ;
- `startup`, 32 с: пуск с минимального уровня, проверка счёта нейтронов.

Что он меряет и что делать:
- Пик и клиппинг → снизить уровни слоёв и шин.
- Щелчки-разрывы (время указано) → найти, что в этот момент стартует, останавливается или скачет; дать рампу. Норма — 0.
- Реакция на события: на сколько дБ меняется спектр после события, без учёта разовых звуков. «Не слышно» — ошибка: событие должно звучать само по себе.
- Жизнь в устойчивых участках (σ громкости). Около 0 — мёртвый гул, нужны биения и медленное блуждание.
- Доля 2–5 кГц (резкость), доля ниже 40 Гц, общая громкость, превышение тревоги над покоем.
- Сходство повторов одного звука: около 1 — одинаковы до сэмпла; у скелета около 0,4.
- Счёт нейтронов: во сколько раз учащаются щелчки при разгоне (у скелета ×10).

Посмотри `audio_*_spectrogram.png`: события должны читаться как перемены, а устойчивые участки — иметь живую фактуру, а не идеально ровные полосы. Автору никогда не пиши «звучит хорошо». Пиши, что измерено, и приложи `audio_default.wav`: финальная проверка — его уши.
